# Contributing to Rising Settlements

Thanks for helping! Bug reports, ideas, translations, house designs and code are all
welcome.

## Reporting a bug

Open an [issue](https://github.com/AmmaarBakshi/Rising-Settlements/issues) and include:

- the mod version, Fabric Loader version and Fabric API version,
- what you did, what you expected and what happened,
- the output of `/settlement info` near the village, if it is about a village,
- `logs/latest.log` (or the crash report) if something broke.

## Setting up

You need **JDK 25** and **Git**. Gradle comes with the wrapper.

```bash
git clone https://github.com/AmmaarBakshi/Rising-Settlements.git
cd Rising-Settlements
./gradlew genSources   # decompiled Minecraft sources for your IDE
./gradlew build        # builds build/libs/rising-settlements-<version>.jar
```

Minecraft 26.3 is not obfuscated, so the code uses Mojang's own names. Before calling a
Minecraft method, look it up in the generated sources instead of guessing its name.

## Testing your change

```bash
./gradlew runClient    # a game with the mod loaded
./gradlew runServer    # a dedicated server (accept the EULA in run/eula.txt first)
```

Villages normally grow over in-game days. For testing, put this in
`run/config/rising_settlements.json` and run `/settlement reload`:

```json
"projectIntervalTicks": 600,
"buildIntervalTicks": 5,
"repairDelayTicks": 100,
"repairIntervalTicks": 5
```

Useful commands (operators): `/settlement info`, `/settlement grow <project>`,
`/settlement repair`, `/settlement reputation @s 50`, `/settlement mayor claim`.

Before opening a pull request, check that:

- `./gradlew build` passes,
- you tried the change in game,
- player-placed blocks near a village are never broken, replaced or built over,
- nothing new runs on the client that should run on the server.

## Code style

- Tabs for indentation, like the rest of the code.
- Every class starts with a short Javadoc saying what it is for. Comments explain *why*
  something is done, not what the next line does.
- World changes happen on the server only. Client code lives in `src/client` and only
  draws screens and effects.
- Keep work spread over ticks: check loaded chunks, and never scan or place large numbers
  of blocks in one tick.
- New player-facing text goes in
  `src/main/resources/assets/rising_settlements/lang/en_us.json` and is used through
  `Lang.tr("your.key")` (the `rising_settlements.` prefix is added for you).
- New options go in `RSConfig`, with a comment, a sensible default and a range check in
  `validate()`. Document them in the README's configuration table.
- All code must be original. Please do not copy code from other mods.

## Adding house designs

House and well templates are generated by
[`tools/TemplateGenerator.java`](tools/TemplateGenerator.java):

```bash
java tools/TemplateGenerator.java
```

You can also build a design in game, save it with a structure block and put the `.nbt` file
in `src/main/resources/data/rising_settlements/structure/house/<style>/` (or in a data
pack). Put the floor at `y = 0` and the front door on the `z = 0` side, and use only
vanilla blocks.

## Translations

Copy `en_us.json` to your language's file name (for example `de_de.json`) in the same
folder and translate the values. Keep the `%s` placeholders.

## Pull requests

1. Fork the repo and create a branch from `main`.
2. Keep each commit focused, with a message that says what changed
   (for example "Let farmers widen existing fields").
3. Open a pull request that explains what changed and how you tested it. Add a line to
   `CHANGELOG.md` under a new "Unreleased" heading.
